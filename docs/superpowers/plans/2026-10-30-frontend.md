# CoworkingBooking v2 — Frontend: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una web Angular sencilla para que clientes reserven espacios en una cuadrícula por fecha, y para que el ADMIN gestione espacios y reservas, lista para probar en local y para desplegar como archivos estáticos en AWS.

**Architecture:** Angular 22 standalone y sin zonas, con signals y `HttpClient`. La lógica que puede fallar sin que se note (horas de Bogotá, estados de la cuadrícula, selección, sesión y mensajes de error) vive en funciones puras con tests. Los componentes solo llaman a la API y pintan. Además, un cambio pequeño en el backend (`GET /api/espacios/todos` y el campo `activo`).

**Tech Stack:** Angular CLI 22.2.5, Node 24, TypeScript ~6.0, Vitest (runner por defecto de `ng test`), CSS propio. Backend: Spring Boot 3.5 (ya existente).

**Spec:** `docs/superpowers/specs/2026-10-30-frontend-design.md` (y la API en `docs/superpowers/specs/2026-10-30-backend-design.md`)

## Global Constraints

- Todo el código del frontend va en `frontend/` (raíz del repo `/Users/david/Documents/proyectos_backend/coworking-booking`).
- Sin librerías extra: nada de Angular Material, NgRx, date-fns ni moment. Solo lo que trae `ng new`.
- Componentes standalone, signals para el estado y `inject()` para dependencias. Sin NgModules.
- Las reglas de negocio las valida el backend. El frontend no valida duración mínima ni máxima ni solapamientos con reservas futuras, y muestra el `detail` del ProblemDetail tal cual.
- Hora siempre de Bogotá: se envía `YYYY-MM-DDTHH:mm:00-05:00` y se muestra convertida a `-05:00`, sin importar la zona del navegador. Las constantes `-05:00`, 07:00, 22:00, bloques de 15 min y 90 días viven solo en `frontend/src/app/config.ts`.
- Rutas normales (sin `#`): `/login`, `/registro`, `/reservar`, `/mis-reservas`, `/admin/espacios`, `/admin/reservas`. La ruta vacía y las desconocidas van a `/reservar`.
- Sesión: `token` y `expiraEn` en `localStorage` con las claves `coworking.token` y `coworking.expiraEn`.
- Textos de la interfaz en español. Mensajes fijos del spec: "Tu sesión expiró, vuelve a iniciar sesión" y "No se pudo conectar con el servidor".
- Comandos del frontend desde `frontend/`: tests `npx ng test --watch=false`, build `npx ng build`. Comandos del backend desde `backend/`: `JAVA_HOME=$(/usr/libexec/java_home -v 21) ./mvnw ...` con Docker encendido.
- Commits en español, terminados en `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Navegador en otra zona horaria** (por ejemplo UTC o Madrid): la cuadrícula y las tablas siguen mostrando horas de Bogotá, y las reservas se envían con `-05:00`. Test en Tarea 4 (`minutosEnBogota` con entrada en `Z` y en `+01:00`).
2. **Franja de ocupación que termina después de las 22:00** (por ejemplo 21:30–22:15 por la limpieza): marca los últimos bloques como ocupados y no falla ni crea bloques fuera de rango. Test en Tarea 4.
3. **Hoy a media mañana** ("ahora" 10:07): el bloque de 10:00 ya cuenta como pasado y no se puede seleccionar. Test en Tarea 4.
4. **Sesión expirada guardada en el navegador** al abrir la app: el guard manda a `/login` sin llamar a la API con ese token. Test en Tarea 3 (`sesionVigente`).
5. **Error sin ProblemDetail** (backend caído, status 0, o una respuesta HTML de un proxy): se muestra "No se pudo conectar con el servidor" o un texto genérico, nunca `undefined` ni `[object Object]`. Test en Tarea 3 (`mensajeDeError`).
